# In-game test checklist — QuickKeybinds 1.0.9

Enable Lua errors with `/console scriptErrors 1`. Test with Blizzard bars first. Open `/qkb`.

- [ ] In English, French and German, open all pages, tooltips and dialogs. Check keyboard modifier/navigation captions, PlayStation shape names, controller center buttons, export/copy-profile buttons, and pending-change counts. Long translated labels should stay within their controls and be readable in full on hover.
- [ ] Try empty/duplicate profile names, invalid imports and unavailable commands: validation messages should use the UI language. Check History backup/recovery labels, date format, percentage spacing and the unsupported-client notice. Native spell/item/action names should retain the game's localized text, and custom profile/macro/device names should remain unchanged.

- [ ] Open every page and scroll long lists. Check the Blizzard frame, gold active tabs, dark controls and grouped content panels. The active tab should look selected and remain readable. Check the window fits your resolution/UI scale, including French labels. Drag it; close/reopen it.
- [ ] Check normal, hovered, pressed and disabled controls. Save should stand out when changes are pending, and become muted after saving/discarding. Use the title-bar close button with a pending draft: it must still ask before closing.
- [ ] Hover bind a visible main-bar button to an unused key. Also try another bar, pet action, stance/form, extra action or vehicle-exit button when present. Check the displayed spell and existing keys match the hovered action.
- [ ] Bind Shift/Ctrl/Alt combinations, middle mouse, mouse buttons 4/5 and the wheel. Confirm bare modifiers and unmodified left/right click do not rebind anything.
- [ ] Bind an already occupied key. Cancel the conflict, then retry and confirm it. Check both the old and new action in the draft. Escape over a hovered action should clear its keys; Escape away from buttons should exit with a dirty-draft prompt.
- [ ] **Before Save**, finish hover mode and test the key: the original live action should still run. Undo/Redo the edit, close/reopen the window, then Discard. No live binding should have changed.
- [ ] Add two or more keys to an action. Replace only one, then remove only one. Confirm the other key remains. Test Clear all and Undo.
- [ ] Save a change, test the action in game, then `/reload`. The saved binding should persist. Disable QuickKeybinds and confirm the key still runs the native action.
- [ ] Search a spell/item/macro name, native action or key. Select an individual category. Check Bound, Unbound, Bars, Pending and Unavailable filters.
- [ ] On Keyboard & Gamepad, confirm a key bound to an action slot shows its spell name/icon (for example, A: Tir des arcanes). Hover for the full name above the keyboard and in the tooltip. Change the spell in that slot or switch bar pages: the display should update. Also check item/macro, pet and stance icons when available, and confirm empty slots clear old spell icons.
- [ ] Change modifier layers and keyboard layouts. Assign a free key to the selected action, then right-click to remove it. The displayed spell/icon must follow that layer and the draft; check Undo/Redo as well. Check colors and full-key tooltips; no live change should occur before Save.
- [ ] On a French client, check arrow/navigation labels stay inside their keycaps, and that the full localized labels still appear on hover. The active Shift/Ctrl/Alt layer should have a gold selection indicator.
- [ ] Check the staggered keyboard, wide Space/Enter/Shift/Tab/Backspace keys, separate arrow cluster and numpad. Click both left/right modifier keys and confirm they toggle the same layer without assigning a bare modifier. Both Enter keycaps should show the same binding; numpad +/Enter should be tall, and numpad 0 wide.
- [ ] Hover F7 and confirm its detail line reads `F7: ...` with no square/unsupported arrow glyph. Check conflict previews, History and the settings minus buttons for missing glyphs too; French accents should still display normally.
- [ ] Click Detect in the keyboard view. Press the first six letter keys after Tab by physical position: check AZERTY, QWERTY or QWERTZ is recognised and applied. Try upper case, partial input, an unsupported sequence, Retry, Cancel and Escape. Only a recognised sequence should change the saved display layout, and binding drafts/live bindings must stay unchanged.
- [ ] Run detection from Settings too, then `/reload` to confirm the display choice persists. Enter combat during the prompt: it should close and release input focus. After changing the OS keyboard input layout, run Detect again. A French client with QWERTY (or another language with AZERTY) should follow the calibration rather than client language.
- [ ] With new settings or **Use client-language default**, check French starts with AZERTY, German with QWERTZ, and other clients with QWERTY. Select a different layout manually or calibrate it, then `/reload`: the override must remain. Reset to the client-language default and verify the expected layout returns without changing any bindings or pending edits.
- [ ] Choose Gamepad, then cycle Xbox, PlayStation and Nintendo labels. Check the controller buttons fit, the left stick/D-pad swap position for PlayStation, and switching labels preserves the draft. Switch back to Keyboard and check its keyboard arrangement is preserved.
- [ ] Set controller labels to Auto. Connect an Xbox, PlayStation or Nintendo controller and confirm the detected device name, effective style and button labels. Disconnect/reconnect it. With two controllers, use the other controller and confirm the visible layout follows it. A pending draft must stay unchanged.
- [ ] Select a manual style, then connect or use another controller: the manual style must remain selected, including after closing/reopening and `/reload`. Return to Auto and confirm detection resumes. With no device or an unknown device style, check the Xbox fallback is clearly labelled.
- [ ] Select an action and assign a controller face button, D-pad direction, trigger/shoulder or stick click. Check spell icons, conflict cancellation/confirmation, right-click removal and Undo/Redo. Modified bindings should appear under the selected Shift/Ctrl/Alt layer.
- [ ] Use Add key and hover mode with a physical controller. Hold a native modifier trigger/shoulder, then press a face button: capture should wait for the face button and record the modified binding. Closing capture/hover mode and entering combat must release controller capture.
- [ ] Save a controller change and `/reload`; verify it works in game and keyboard bindings remain unchanged. Export/import a profile containing both input types. Disconnect/reconnect the controller and check the view refreshes. Native input/movement/modifier settings should remain as you configured them in WoW.
- [ ] Create, duplicate, rename and delete a profile. Change bindings, preview the profile, cancel, then preview/apply it. Applying must change only the draft. Undo should restore the previous draft.
- [ ] Export a profile/draft and import it again. Confirm the preview. Try malformed text and an unknown command: those must not change the draft or execute anything.
- [ ] Save a change, then restore its preceding backup in History. Check the selected scope shown in the preview. Apply to draft and Save to restore the earlier bindings.
- [ ] With a clean draft, switch Account/Character. Confirm merely inspecting a different scope leaves the live bindings alone. Save a distinct character binding; verify on another character that the account bindings remain independent. A dirty draft must block switching scope.
- [ ] Make a draft, enter combat, and try editing/saving. Capture and overlays must pause, and no change should be saved. Leave combat and confirm the draft remains and hover mode resumes.
- [ ] With a draft pending, change a binding using Blizzard's binding panel. QuickKeybinds should block Save and offer Reload/Rebase. Rebase must show which keys it overwrites and retain unrelated external changes.
- [ ] With an addon that owns `/kb` enabled, confirm `/qkb` always opens QuickKeybinds and the other addon's command still works. Avoid enabling both binding modes together.

For an issue report, include the client build from `/dump GetBuildInfo()`, the exact error, your UI language/scale, the page/action, and whether you were in combat or using another binding addon.
